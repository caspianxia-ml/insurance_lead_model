# 保险福利线索模型 V1.1：定义、实验设计与数据登记

状态：2026-10-21 精简版 `_1200` 全国 P/U1 通过结构门槛，C/D 已分别运行。结果见 `V1_1_RESULTS_1200.md`；本文保留实验定义和历史输入问题。

## 1. V1.1 是什么

V1.1 是 V1 的**验证体系和数据快照升级**。目标是在保留 V1 四个模型及特征定义的前提下，回答两个可区分的问题：

1. 补上实体级交叉验证、固定留出集和 U 的折外评分后，原 V1 排序有多稳定？
2. 换用 2026-10-20 中午导出的新 U1 和新 P 后，候选名单及已知 P 的样本外排序发生什么变化？

四个模型仍为 Positive Similarity、Repeated Sampled-U Logistic Regression、One-Class SVM、Isolation Forest。不加入 nnPU，不扩大到 U2/U3，不把 U 当真实负类，不把分数称为参保概率。V1 原代码、配置、输出保持原样；V1.1 用独立入口、分支和带运行编号的本地产物。

## 2. 样本、标签与实体

- **P**：已知有保险福利证据的企业，标签来源和质量等级必须单独登记。`p_quality`（如 Gold/Silver）的定义、数量及是否混合训练须在运行 D 前核查和确认；不把所有新 P 默认为同质正例。
- **U1**：沪苏范围、福利线口径的未标注企业。U 不等于负例，且可含已知 P，必须先按标准化信用代码排除与所有已知 P 重合的实体。
- **实体键**：标准化的统一社会信用代码。缺失、重复、异常经营、P/U 冲突及其处理数量逐步记录；不按行号切分，不拼接多条企业记录的非空字段。
- **时间**：用户声明这轮 P/U1 属于 2026-10-20 中午数据快照。文件名和文件修改时间只能作辅助证据；正式 manifest 同时记录用户声明、文件 SHA-256、字节数、修改时间、实际记录数和导出 SQL/口径（若可取得）。两份 P CSV 的文件修改时间为 2026-10-21 上午，不能把它误写成数据库快照时间。

## 3. 对照实验

| 实验 | P 训练口径 | U 口径 | 目的与边界 |
| --- | --- | --- | --- |
| A | 历史 V1 P | 历史 V1 U1 | 原流程和原始输出的只读基准 |
| B | 与 A 相同 | 与 A 相同 | 只改变验证体系：固定 P 留出、P 训练部分 5 折、全 U 的 LR 5 折 OOF |
| C | 与 B 相同 | 2026-10-20 新 U1 | 只改变 U 快照；新 P 仅用于排除已知正例，不进入训练 |
| D | 2026-10-20 新 P，按确认后的质量等级口径 | 同一新 U1 | 用户本轮要求的 P＋U1 数据更新实验；与 C 分开运行，不能将 C/D 差异归因为单一因素 |

B/C 在相同历史 P 留出集和两轮共有、未被任何已知 P 标记的 U 实体上比较。D 训练前须从新 P 中移出冻结的历史 P 留出实体，保证留出集对 D 仍是样本外；B/C/D 的正式可比指标再取共同且未进入任一训练池的评价实体交集。若新 P 标签口径与历史 P 不一致，应分别报告，不能直接宣称模型优劣。A/B 为历史运行；本轮 C/D 独立运行，结果另见 `V1_1_RESULTS_1200.md`。

## 4. 验证与评分规则

- 固定、可追溯的实体级 P 留出集不参与任何模型或预处理拟合。其余 P 做 5 折验证，记录每折训练/验证实体清单、已知 P 在候选总体中的排名和 Top-K 捕获率。
- Repeated Sampled-U LR 对每个 U 用 5 折 cross-fitting：每个 U 至少取得一次未用自身拟合的 OOF 分数。记录折间分数分布、分数方向、随机种子、重复抽样次数、Top-K 交集和排名相关。
- Positive Similarity、One-Class SVM、Isolation Forest 按实际训练逻辑核对是否仅用 P 拟合；若是，可直接评分全 U。所有填充、编码、标准化和特征准入只在对应训练折拟合。
- 继续使用 V1 的画像特征白名单。来源、标签、福利规则、地域、标识符、公司名、联系方式、Raw 计数等不得作为预测特征。新增数据只复用特征**定义**，不复用旧预处理器的拟合参数。
- 对不进入模型的自由文本和联系字段，可在导出 SQL 中保留 `has_*` 有无标记，供数据质量与增量 EDA 使用。0 表示 `NULL`、空字符串或仅空白字符，1 表示有非空内容；JSON 型字段的空对象/空数组需单独界定并记录。标记只反映字段是否有值，不代表信息真实、有效或企业具有保险福利。
- 首批审计标记可包括 `has_company_introduction`、`has_business_scope`、`has_score_details`（仅 P）、`has_remark`（仅 P）、`has_contact_phone`、`has_contact_email`。它们可能直接编码来源、采集覆盖或标签生成过程，**不得进入任何一折的 X、特征准入或模型拟合**；EDA 按 P/U、来源与快照分组呈现其覆盖率，不解释为企业业务特征的因果差异。
- U 没有真负标签，不计算把 U 当负例的 AUC、F1、Precision 或 Accuracy。已知 P 的 Top-K 捕获率是样本外排序检查，不是新线索的真实精确率。

## 6. 可复现交付与 Git 约束

每组实验有独立 `runs/<run-id>/`：输入 manifest（含路径、哈希、时间、版本、种子、参数）、逐步清洗漏斗、排除原因、特征准入、实体划分、交叉验证和 OOF 检查、固定评价集指标、全量新 U1 评分、Top-K 候选、增量 EDA、中文结果报告。源文件、企业级明细、评分文件只在本机保存并由 Git 忽略；Git 只提交代码、测试和不含企业记录的文档，不自动推送。任何失败运行保留诊断并标记未完成，不编造结果。

当前可复现的历史 B 入口、数据口径和结果见 `V1_1_AUDIT_AND_RUNBOOK.md`、`V1_1_RESULTS_B.md`。本轮 C/D 的实际命令、输入哈希及结果见 `V1_1_RESULTS_1200.md` 和各运行目录的 manifest。
