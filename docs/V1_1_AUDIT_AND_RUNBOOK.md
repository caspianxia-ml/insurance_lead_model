# 保险福利模型 V1.1：审计记录与运行约定

## 目的与边界

V1.1 是 V1 的验证和数据快照升级，不是 V2 或 nnPU 实验。本版本固定保留四个 V1 排序器：

1. Positive Similarity；
2. Repeated Sampled-U Logistic Regression；
3. One-Class SVM；
4. Isolation Forest。

V1.1 的主要比较为：A（历史旧 P + 旧 U1、原流程）、B（相同旧数据 + CV/OOF）、C（相同 P + 新 U1 + CV/OOF）。新 P 只能作为“排除已知正例”的审计输入；是否用于训练是单独的 D 实验，必须由用户明确确认后才可运行。U2、U3 不属于本轮范围。

## 实际清洗逻辑复核

当前代码的真实规则如下，不能用口头历史规则替代：

| 项目 | 代码实际行为 | V1.1 处理 |
| --- | --- | --- |
| 企业键 | 标准化 `credit_code`（NFKC、去空白、转大写）；空值排除 | 保持；记录格式/校验和异常，但仅空值排除 |
| 去重 | `profile_completeness` 降序，再按原始输入顺序升序 | 与“更新时间最新 → ID 最大”不一致；V1.1 必须明确采用哪一种并写入 run manifest |
| 异常经营 | 含 注销、吊销、撤销、清算、终止、关闭、歇业、迁出 即排除 | 保持并逐条审计 |
| P/U 冲突 | U 中匹配 P 的信用代码被移除 | V1.1 会将训练 P、仅排除 P、及其作用分别报告 |
| 地域/福利线 | 当前代码只做地域纠正审计，不执行地域或福利线筛选 | 输入文件必须在 manifest 中声明已按 U1 口径导出，不能假设代码已筛选 |
| 字段/缺失 | 金额、日期、人数和分类字段标准化；原始值不覆盖 | 每次运行记录 schema、类型、缺失率与解析状态 |

注意：当前 P/U 冲突判断使用的是清洗前 P 的信用代码集合；这比“仅用最终保留 P”更保守，且需在 V1.1 中单独复核。公司年龄目前依赖运行当天，V1.1 必须改为配置中的冻结参考日期。

## V1.1 数据交付与运行规则

完整 A/B/C 运行前需提供三个明确的原始数据路径：历史 P、历史 U1、新 U1。B 可先用已保存的清洗后快照，但须标记为“快照复核”，不能宣称原始数据重新清洗。每个实际输入写入本地 `runs/<run-id>/manifest.json`，记录绝对路径、文件 SHA-256、文件修改时间、行数、字段、快照时间和导出 SQL/口径说明（若可提供）。原始文件不复制、不改名、不提交。

新 P 如需参与，仅可先用于“新 P 与新 U1 的实体冲突审计”；D 实验必须以独立 run id、独立配置、独立结果目录运行，且收到明确确认后执行。

新导出可先用 `python3 -m experiments.validate_export <CSV绝对路径>` 检查 CSV 列宽与转义。输出仅含统计、校验和及异常记录序号，不显示企业内容。若仅用于排除已知 P，单列 `credit_code` 导出即可，但仍需记录其快照时间和来源口径。

每次 A/B/C 运行输出到本地、被 Git 忽略的 `runs/<run-id>/`：清洗漏斗、排除明细、数据质量、快照 manifest、特征准入、固定 holdout 清单、5 折清单、OOF 分数、全量 U1 分数、Top-K、稳定性、依赖版本和中文报告。代码、测试、示例配置和不含企业数据的文档才进入 Git。

## 已知基线限制（待 V1.1 修复）

- V1 使用单次 80/20 P holdout，未做实体级 P K-Fold。
- V1 仅评分未进入 U fit pool 的 60% U；LR 不提供全 U OOF。
- `requirements.txt` 未固定依赖版本；审计环境为 Python 3.13.6、NumPy 2.3.2、pandas 2.3.2、scikit-learn 1.7.1、matplotlib 3.10.5。
- V1 的四种分数是排序分数，不能作为校准概率；U 不是可靠负类，不报告以 U 为真负类的 AUC、F1 或 Precision。
