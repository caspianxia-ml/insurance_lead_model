# V1.1：2026-10-20 12:00 口径 P/U1 实验记录

状态：2026-10-21。A 为原 V1 归档结果；B 为历史清洗快照的验证补全；C、D 分别使用本轮精简版 U1 及 P。所有企业级结果只保留在 Git 忽略的本机 `runs/`。本报告只含汇总统计，不是独立业务核验结论。

## 定义和输入

- C：历史清洗后 P 5,698 家固定，只换新 U1；新 P 仅用于排除已知正例。
- D：新全国 P＋同一新 U1；Gold 和 Silver 都作为观察正例，原力来源的 Gold 只是较高可信**候选**，并非人工核验真值。D 从新 P 训练池中排除历史固定 P holdout。
- 四模型和 V1 特征白名单不变：Positive Similarity、Repeated Sampled-U LR、One-Class SVM、Isolation Forest。所有统计型预处理在对应训练部分拟合；LR 对 U 做 5 折 cross-fitting。随机种子 42、123，LR 重复抽样 10 次，特征年龄参考日期 2026-10-20。
- 新 P 输入 `V2_P_National_20261020_1200.csv`（40,033 行、27 列）；新 U1 输入 `V2_U1_20261020_1200.csv`（18,376 行、20 列）。两份均通过严格 CSV 解析、无列宽不匹配。确切哈希、字节数、文件修改时间和依赖版本以各运行 manifest 为准。
- 文件名中的中午时间及用户声明不等于严格历史数据库快照。精简 U1 的福利线 Raw 筛选条件无法从 CSV 内单独复核；`is_shanghai`、`is_suzhou` 只用于检查沪苏范围，不入模。

## 数据质量与清洗

| 项目 | 本轮结果 |
| --- | ---: |
| 新 P 原始行数 | 40,033 |
| 新 P 非空信用代码的不同实体 | 35,434 |
| 新 P 按 V1 清洗后的实体 | 35,332 |
| 新 P 训练实体（排除固定历史留出） | 34,193 |
| 新 U1 原始行数 | 18,376 |
| C 新 U1 经历史 P 排除与 V1 清洗后 | 13,914 |
| C 再排除与新 P 重合实体 | 2,511 |
| C/D 最终新 U1 评分实体 | 11,403 |
| B/C/D 共用冻结 U 评价实体 | 6,433 |
| 固定历史 P 留出实体 | 1,140 |

按原始导出直接比较，新 P/U1 有 6,960 个相同信用代码；它不是在历史 P 排除后的 C 第二步冲突数。D 先排除新 P，再额外排除 4 个只在历史 P 中识别到的 U 实体，最终与 C 的 11,403 个 U 实体集合完全一致。各步逐条排除原因在本机 `quality/`，不得把原始重合数与清洗后漏斗数混用。

原始 P 的 Gold 为 7,556 行、Silver 为 32,477 行；清洗后分别是 3,198 和 32,134 个实体。Gold 原始行高度重复（约 3,203 个不同信用代码），不能拿原始 Gold 行数当作 Gold 企业数。Gold/Silver 分组来自来源线索，后续 V2 仍需独立质量核验。

## 冻结评价集上的结果

下表是在相同 **1,140 个历史已知 P 留出实体＋6,433 个共用 U 实体**上，已知 P 排入前 10% 的比例。U 不是真实负例，因此这不是业务召回率、Precision 或 AUC；不同 P 训练口径的结果也不构成因果解释。

| 模型 | C：历史 P＋新 U1 | D：新 P＋新 U1 |
| --- | ---: | ---: |
| Positive Similarity | 7.02% | 12.72% |
| Sampled-U LR | 38.25% | 36.49% |
| One-Class SVM | 6.75% | 8.77% |
| Isolation Forest | 3.95% | 20.18% |

C/D 在 6,433 个共用 U 上的 Spearman 排序相关分别为 Similarity 0.832、LR 0.699、One-Class SVM 0.920、Isolation Forest 0.536；Top 100 Jaccard 分别为 0.258、0.481、0.198、0.220。换 P 后名单变动明显，尤其 Isolation Forest。这个现象需要 V2 的来源、Gold/Silver 和特征消融来解释，不能直接宣称 D 更好。

C 的两种随机种子下，LR 全 U 分数 Spearman 为 0.968，Top 100 Jaccard 为 0.724。完整折间分数尺度和 D 的稳定性见本地 `U_lr_fold_scale.csv`、`U_lr_seed_stability.csv`。

## 可复现运行与产物

在项目根目录、安装 `requirements.txt` 的 Python 环境下运行；每次使用**尚不存在**的 run ID，避免覆盖旧结果。实际最终运行 ID、runner SHA-256 和输入哈希记在各自的 `manifest.json`。

```bash
.venv/bin/python -m experiments.v1_1_new_u1_c \
  --run-id 20261021_C_1200_verified \
  --new-u1 V2_U1_20261020_1200.csv \
  --positive-exclusion V2_P_National_20261020_1200.csv \
  --reference-date 2026-10-20

.venv/bin/python -m experiments.v1_1_new_p_d \
  --run-id 20261021_D_1200_verified \
  --new-p V2_P_National_20261020_1200.csv \
  --new-u1 V2_U1_20261020_1200.csv \
  --c-run runs/20261021_C_1200_verified \
  --reference-date 2026-10-20
```

每个运行目录含 manifest、清洗漏斗和排除明细、固定评价集、P 交叉验证、所有新 U1 的四模型评分及排名、Top 100、LR 折尺度/种子稳定性及中文摘要。D 另外保存 C/D 共用 U 排序对照、Gold/Silver 分层计数及精简缺失率 EDA。

## 尚未解决的问题

1. 历史 A 的原始旧 P/U1 导出未定位，B 只能从 2026-10-08 清洗后快照复现；不能声称完整复跑了原始 V1 清洗。
2. 新 P 的来源可信度尚未通过业务独立核验；Gold/Silver 不是真实标签噪声率。
3. 中午口径并非严格历史快照；U1 福利线筛选 SQL 条件未随精简文件提供，无法从 CSV 独立验证。地区与来源的偏差只做审计，不入 V1.1 模型。
4. 已知 P 的 Top-K 捕获率仅反映观察正例。新线索真实发现率必须对候选名单抽样人工核验。
5. U2/U3、地区与信息完整度特征、nnPU 和 Gold-only 对照属于 V2，不混入本轮 V1.1。
