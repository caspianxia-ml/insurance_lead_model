# 企业保险福利识别 V2 | 数据规范（草案 v0.1）

**状态：定义已整理，原始数据待验收。**

## 数据集及角色

| 名称 | 定义 | 备注 |
|---|---|---|
| `P_national` | 全国带有效“保险福利”标签的正样本候选 | 来自 Leads+标签；不等于 Gold 已确认 |
| `P_shanghai` | `P_national` 中沪企子集 | 应派生，不能当成新增样本与全国 P 拼接 |
| `U1` | 历史沪苏福利线未标注候选 | V1 历史快照；与 U2/U3 不必然严格包含 |
| `U2` | 全国福利线未标注候选，Mid Clean | 允许已有 Leads 记录 |
| `U3` | 全国广义企业候选，Mid Clean | 允许已有 Leads 记录；不因缺少少量工商特征而直接弃行 |

- 在统一数据时点、标签与清洗口径下，计划关系是 `U1 ⊆ U2 ⊆ U3`；实际历史快照必须审计后才能声称成立。
- 训练前把 U 中信用代码与已确认 P 重合的实体排除。信用代码不完整、同名异码等情况转人工复核，不仅凭名称自动剔除。
- 同实体去重使用信用代码；优先保留完整度最高、再保留更新较新的记录。禁止任意跨记录拼接字段。
- 沪苏地域筛选口径：`registered_address` 或 `company_name` 含 `上海` / `苏州`。不依赖省市标签；地域用于样本选择/分组审计，不作为 V1 基线预测特征。

## 信用代码与缺失

1. 保留原始 `credit_code`，以字符串读取，防止科学计数法、数字截断和前导字符丢失。
2. 规范化只做 Unicode/空白清理和大小写一致；仅 18 位字母数字可用于首轮严格实体匹配（格式符合不代表校验位合法）。
3. 代码缺失、不合 18 位格式、疑似 Excel 浮点/科学计数法的公司：**保留并标记为待核验**，不默认删除。
4. 无信用代码的同名企业仅人工复核；不能当作确定相同实体。

## Gold / Silver P

- `Gold`：存在**独立、可靠的业务确认依据**，且确认的是“企业向员工提供保险福利”。
- `Silver`：符合现有保险福利打标规则，但无上述独立确认依据。
- `source` 包含“原力”只标记为 Gold **候选**，不能直接转成 Gold。
- 正例判定与关键词/页面福利标签属于标签证据，不能作为模型预测特征；外呼后结果也不能泄漏到模型中。
